# 입지 분석(스코어보드) 데이터

상세 패널의 **입지 분석** 탭이 쓰는 데이터를 만드는 곳입니다.

공고 한 건을 다섯 축으로 채점합니다.

| 축 | 가중치 | 무엇을 보나 |
|---|---|---|
| 분양가 | 28% | 분양 평당가 ÷ 인근 단지 전용 84㎡ 실거래 평당가 |
| 시세흐름 | 18% | 동 단위 실거래 1년·3개월 변동률 |
| 개발호재 | 18% | 노선·산업단지·정비사업을 단계와 시점으로 할인해 합산 |
| 인프라 | 18% | 역·초등학교·중학군·공원·마트·의료 실측 거리 |
| 청약수요 | 18% | 실제 청약 경쟁률 + 생활권 커뮤니티 반응 |

점수 산식은 앱의 "점수는 어떻게 매겼나"에 그대로 노출됩니다. 숨은 계산은 없습니다.

## 데이터 파일

| 파일 | 크기 | 언제 로드되나 |
|---|---|---|
| `src/data/scoreboard-index.json` | 3KB | 초기 번들. 목록 카드의 점수 배지·배수에 쓰입니다 |
| `src/data/scoreboard.json` | 287KB | **입지 분석 탭을 처음 열 때만** 동적 import 됩니다 |

목록에 배지를 띄우려면 전 공고의 점수가 필요하지만 상세 내용은 탭을 열어야 필요하므로 둘로 나눴습니다.
덕분에 초기 번들은 gzip 기준 약 7KB만 늘어납니다.

## 다시 만들기

```bash
node scripts/scoreboard/build-scoreboard.mjs <dataset.json>
```

`dataset.json` 은 아래 수집·스코어링 파이프라인이 만든 전체본(약 850KB)입니다.
이 저장소에는 결과 두 파일만 커밋돼 있고, 수집 원천(약 2.3MB)은 용량과 외부 서비스 재배포 문제로 제외했습니다.

### 파이프라인

원천 수집과 스코어링은 별도 도구에서 돌립니다. 순서는 이렇습니다.

1. **공고 → 단지 매칭** — 공고 제목으로 단지를 찾아 좌표·세대수·시공사·입주예정월을 얻습니다.
2. **인근 단지 탐색** — 같은 동에서 반경·세대수 기준으로 비교 단지를 최대 6곳 고릅니다.
   농촌·신도시처럼 표본이 없는 곳은 도시명 키워드로 다시 찾습니다.
3. **평형별 상세** — 주택형별 전용/공급면적, 분양가, 실거래가, 청약 경쟁률, 당첨 최저가점,
   학군(중학교 학업성취도 백분위 포함), 역·공원·마트·의료 실측 거리를 모읍니다.
4. **커뮤니티** — 공개 리뷰는 단지당 3건이 상한이라 인근 단지 리뷰까지 합쳐 생활권 표본으로 씁니다.
5. **개발호재 큐레이션** — 노선·산단·정비사업의 진행 단계를 공개 보도·지자체 자료로 확인해 손으로 정리합니다.
   계획 0.30 / 추진 0.55 / 착공 0.85 / 개통 1.00 에 시점 할인을 곱해 현재가치로 환산합니다.
6. **스코어링** — 위 다섯 축을 계산하고 산식 문자열까지 함께 내보냅니다.

### 개발호재를 갱신하려면

가장 자주 바뀌는 건 5번입니다. 노선 개통이 밀리거나 착공이 나면 큐레이션을 고치고
파이프라인을 다시 돌린 뒤 이 스크립트로 두 JSON을 재생성하면 됩니다.

점수는 투자 권유가 아니라 공고들을 같은 잣대로 비교하기 위한 상대 지표입니다.
앱의 "읽을 때 유의할 점"에 한계를 항상 표시하며, 특히 이 세 가지를 감안해서 보세요.

- 커뮤니티 감성은 한국어 키워드 규칙 기반 추정치입니다. 반어·이중부정에 약해 원문을 함께 싣습니다.
- 인근 단지 시계열은 단지 대표 주택형 기준이라 **지수(구간 시작 = 100)로만** 비교할 수 있습니다.
- 토지임대부 주택은 건물분만 분양하므로 분양가 점수에서 제외했습니다.
